# SHFF Dock

Панель управления контейнерами на своём железе. Ядро на Node ходит в докер на
хосте и раскладывает сервисы по `/home/dock/stacks`, панель на React рисует то,
что ядро отдаёт.

```
shff-dock/
├── apps/
│   ├── api/          ядро: fastify + dockerode + docker compose
│   └── web/          панель: vite + react
├── packages/
│   ├── shared/       контракт: доменные типы, пути ручек, события сокета
│   └── ui/           дизайн-система SHFF в виде React-компонентов
├── _ds/              вендоренная дизайн-система (токены, css, бандл)
├── install.sh        установка на чистую машину одной командой
├── Dockerfile
└── docker-compose.yml
```

## Установка

На чистой Debian или Ubuntu — одной командой:

```bash
curl -fsSL https://raw.githubusercontent.com/Heisenberg4441/shff-dock/master/install.sh | sudo bash
```

Скрипт обновляет пакеты, ставит докер с плагином compose, готовит `/home/dock`,
поднимает панель из готового образа и в конце печатает адрес, по которому она
открылась. Собирать ничего не нужно — образ уже лежит на Docker Hub. Повторный
запуск той же команды обновляет панель и не трогает данные.

Настройки, если нужны другие:

```bash
curl -fsSL .../install.sh | sudo bash -s -- --port 8080 --no-upgrade
```

`--no-upgrade` пропускает `apt upgrade` всей машины — по умолчанию он делается.

### Из исходников

```bash
docker compose up -d --build   # панель на http://<хост>:7788
```

`/home/dock` панель создаёт сама, общую docker-сеть тоже, реестр готовых стеков
подтягивается с гитхаба. Единственное требование к первому запуску — доступ в
сеть: в образе стеков нет.

Разработка без докера:

```bash
npm install
npm run build -w @dock/shared
npm run dev            # ядро на :7788 (mock) + панель на :5173
```

## Сборка и публикация

`.github/workflows/ci.yml` гоняет тайпчек и сборку на каждый пуш и pull request.
`.github/workflows/docker.yml` собирает мультиархитектурный образ
(`linux/amd64`, `linux/arm64`) и публикует его на Docker Hub как
`heisenberg4441/shff-dock`: пуш в `master` уезжает в `:latest` — тот самый, что
тянет `install.sh`, — и дублируется тегом `master-<sha>` на случай отката. Тег
`v1.2.3` даёт `:1.2.3` и `:1.2`.

Публикация требует двух секретов в Settings → Secrets and variables → Actions:
`DOCKERHUB_USERNAME` и `DOCKERHUB_TOKEN` (Access Token с правом Read & Write, не
пароль).

## Раскладка на хосте

Всё, что панель создаёт, лежит в одном месте и нигде больше:

```
/home/dock/
├── stacks/<id>/          стек целиком
│   ├── stack.yaml        манифест, по которому он поставлен
│   ├── compose.yaml      то, что реально исполняется
│   ├── .env              значения инпутов (0600)
│   ├── <конфиги>         отрендеренные prometheus.yml, datasources и прочее
│   └── data/             тома сервисов
├── registry/             кэш скачанных манифестов
├── backups/
├── dock.yml              настройки панели
└── state.json
```

Каталог стека самодостаточен: скопировал на другую машину, `docker compose up -d`
— получил тот же сервис. Своей базы у панели нет.

Путь `/home/dock` одинаков внутри контейнера панели и снаружи — иначе
bind-монтирования, которые панель пишет в compose-файлы стеков, не разрешились
бы на хосте. Менять его можно, но только целиком, переменной `DOCK_ROOT`.

## Формат стека

`stack.yaml` (apiVersion `dock/v1`) описывает сервис так, чтобы он приезжал уже
настроенным — с конфигами соседей, а не «вот образ, дальше сам».

```yaml
apiVersion: dock/v1
kind: Stack
id: observability
name: grafana + prometheus + loki
version: 1.0.0
category: мониторинг
summary: 'Наблюдаемость из коробки.'
primary: grafana                 # чей порт и журнал показывать на карточке

inputs:                          # из них панель строит форму установки
  - key: PORT                    # ключ = имя переменной окружения
    label: Порт grafana
    type: port
    default: 3000
    hostPort: true               # панель проверит, что порт свободен
  - key: ADMIN_PASSWORD
    type: secret
    generate: password           # пустое поле → сгенерируется
  - key: ENABLE_LOKI
    type: bool
    default: true

profiles:                        # родные compose-профили, включаемые булевым инпутом
  - name: loki
    when: ENABLE_LOKI

volumes:                         # создаются заранее и с нужным владельцем
  - path: data/grafana
    owner: '472:0'

files:                           # рендерятся в каталог стека
  - path: prometheus/prometheus.yml
    template: files/prometheus.yml.tmpl
  - path: grafana/provisioning/datasources/loki.yaml
    template: files/ds-loki.yaml.tmpl
    when: ENABLE_LOKI

compose: compose.yaml            # либо compose-документ прямо здесь

post:
  url: 'http://${DOCK_HOSTNAME}:${PORT}'
  notes: 'Пароль: ${ADMIN_PASSWORD}'
```

Три решения, на которых стоит формат:

**Compose не переизобретается.** Значения инпутов ядро кладёт в `.env` рядом с
compose-файлом, подстановку `${PORT}` делает сам docker compose. Зависимости,
профили, healthcheck'и и пересоздание изменившегося — тоже его работа.

**Свой шаблонизатор умеет ровно одно — `${VAR}`.** Он нужен только для конфигов
сервисов (`prometheus.yml` и подобных), которые compose не трогает. Условий и
выражений в шаблонах нет намеренно: файл стека должен читаться как файл, а не
как программа. Необязательные части включаются через `when` у файла и профили у
сервисов. Экранирование как в compose: `$$` даёт литеральный `$` — это нужно
там, где `${1}` значит своё, например в relabel-правилах prometheus.

**Ключ инпута — это имя переменной окружения.** `ADMIN_PASSWORD` попадает в
`.env`, в шаблоны и в compose под одним именем, без отдельного пространства имён.

Переменные, которые подставляет само ядро: `DOCK_STACK_ID`, `DOCK_STACK_DIR`,
`DOCK_DATA_DIR`, `DOCK_NETWORK`, `DOCK_TZ`, `DOCK_DOMAIN`, `DOCK_HOSTNAME`,
`DOCK_PUID`, `DOCK_PGID`. Перекрыть их инпутом нельзя.

Порядок установки: манифест → файлы и каталоги данных с владельцем → и только
потом `compose up`. Обратный порядок — самая частая причина «поставилось, но
упало»: докер создаёт недостающий каталог от root, а grafana (uid 472) писать в
него не может.

### Реестр стеков

Стеки в образе не лежат — они живут отдельным репозиторием
[Heisenberg4441/shff-registry](https://github.com/Heisenberg4441/shff-registry)
и приезжают по HTTP:

```
shff-registry/
├── registry.yaml
└── stacks/
    ├── observability/{stack.yaml,compose.yaml,files/*}
    └── vaultwarden/stack.yaml
```

Так каталог пополняется коммитом в реестр, а не пересборкой образа и
переустановкой панели у всех сразу. Индекс перечитывается при старте, раз в час
(`DOCK_REGISTRY_TTL`) и по кнопке в каталоге. Скачанное кэшируется в
`/home/dock/registry`, поэтому недоступный гитхаб не ломает уже установленные
стеки и не мешает ставить новые из кэша — пустой каталог бывает только на первом
запуске без сети.

Свой реестр подключается переменной, формат тот же:

```bash
DOCK_REGISTRY_URL=https://raw.githubusercontent.com/youruser/your-stacks/master
```

Если вы пишете стеки, каталог на диске подключается через
`DOCK_BUNDLED_REGISTRY` — он идёт в основу, удалённый накладывается сверху:
одноимённые стеки перекрываются, остальные добавляются.

## Метрики хоста

Изнутри контейнера `/proc/meminfo` и `statfs('/')` показывают то, что выделено
докеру: на машине с 64 ГБ панель рисовала 30. Поэтому compose монтирует хостовые
`/proc`, `/sys` и корень в `/host/*`, а ядро читает их оттуда. Ограничения cgroup
самого контейнера панели игнорируются — к железу они отношения не имеют.

Если хост не примонтирован, метрики отдаются с пометкой `truthful: false`, и
панель честно пишет об этом полосой сверху вместо красивой неправды.

## Архитектура

**Драйвер — единственное место, где ядро трогает хост.** Интерфейс
`DockerDriver` (`apps/api/src/core/driver.ts`), две реализации:

| Драйвер | Когда | Что делает |
|---|---|---|
| `MockDriver` | `DOCK_DRIVER=mock` | Выдуманный хост в памяти, собранный по тем же манифестам: стек из пяти сервисов и в моке будет пятью контейнерами. Докер не нужен. |
| `DockerodeDriver` | `DOCK_DRIVER=docker` | Настоящий демон. Читает состояние через dockerode (инспект, статистика, журналы), а всё, что меняет мир, делает через `docker compose` поверх каталога стека. |

Разделение намеренное: инспект должен быть быстрым и частым, а изменения —
воспроизводимыми файлами на диске, а не последовательностью вызовов API, которую
потом никто не повторит руками.

**Поток данных.** Один вебсокет `/api/stream` отдаёт снимок при подключении, а
дальше только дельты: строки журнала, обновления сервисов, метрики хоста,
прогресс задач, изменения реестра. Пока сокет живой, панель сервер не опрашивает.
Долгие операции возвращают `Job` сразу, прогресс уезжает событиями — HTTP-запрос
не висит, пока тянутся образы.

**Стек — одна карточка.** Контейнеры группируются по метке
`com.docker.compose.project`, статус и ресурсы сворачиваются. Контейнеры,
поднятые мимо панели, показываются отдельно и помечаются как чужие.

**Дизайн-система.** `_ds/shff-design-system-…/` — как её отдаёт сборщик DS, не
правится. `packages/ui` — те же компоненты в TSX, разметка и классы один-в-один.
Обновить — заменить папку в `_ds/` и путь в `apps/web/vite.config.ts`.

## Переменные окружения

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `PORT` | `7788` | Порт панели |
| `DOCK_DRIVER` | `mock` | `mock` или `docker` |
| `DOCK_ROOT` | `/home/dock` | Корень раскладки |
| `DOCK_REGISTRY_URL` | `…/shff-registry/master` | Репозиторий со стеками (raw-адрес) |
| `DOCK_REGISTRY_TTL` | `60` | Как часто перечитывать реестр, мин; `0` — только вручную |
| `DOCK_BUNDLED_REGISTRY` | — | Реестр на диске в основу удалённого |
| `DOCK_DOCKER_SOCKET` | `/var/run/docker.sock` | Сокет демона |
| `DOCK_NETWORK` | `dock` | Общая сеть панели и стеков |
| `DOCK_ADOPT_FOREIGN` | `true` | Показывать чужие контейнеры |
| `DOCK_PUID` / `DOCK_PGID` | `1000` | Владелец каталогов данных |
| `DOCK_PROC_ROOT` | `/host/proc` | Хостовый procfs |
| `DOCK_ROOTFS` | `/host/rootfs` | Хостовый корень для места на диске |
| `DOCK_POLL_INTERVAL` | `4000` | Период пересчёта метрик, мс |

## Известные ограничения

- Шрифты подтягиваются с Google Fonts — так их подключает дизайн-система. Для
  офлайнового билда положить `.woff2` и переписать `_ds/…/tokens/fonts.css`.
- Экран настроек пишет `dock.yml`, но не применяет его к хосту: прокси, TLS и
  cron бэкапов — конфигурация соседних сервисов, а не самой панели.
- `post.health` в манифесте разбирается, но проверку готовности ядро пока не
  выполняет — статус берётся из состояния контейнеров.
- Аутентификации у панели нет: она рассчитана на loopback за reverse proxy.
- Панель ходит в докер-сокет, то есть имеет права root на хосте. Наружу её
  выставлять нельзя.
