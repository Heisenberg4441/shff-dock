# SHFF Dock

Панель управления контейнерами на своём железе. Прототип `SHFF Dock.dc.html`
превращён в рабочее приложение: ядро на Node ходит в докер на хосте, панель на
React рисует то, что ядро отдаёт.

```
shff-dock/
├── apps/
│   ├── api/          ядро: fastify + dockerode, раздаёт API и собранную панель
│   └── web/          панель: vite + react, ходит в ядро по HTTP и вебсокету
├── packages/
│   ├── shared/       контракт: доменные типы, пути ручек, события сокета
│   └── ui/           дизайн-система SHFF в виде React-компонентов
├── _ds/              вендоренная дизайн-система (токены, css, бандл)
├── Dockerfile        один образ: ядро + собранная панель
└── docker-compose.yml
```

## Быстрый старт

```bash
cp .env.example .env
docker compose up -d --build
# панель на http://<хост>:7788
```

Без докера, для разработки:

```bash
npm install
npm run build -w @dock/shared
npm run dev            # ядро на :7788 (mock) + панель на :5173
```

## Архитектура

### Драйвер — единственное место, где ядро трогает хост

Всё, что панель умеет делать с контейнерами, описано интерфейсом `DockerDriver`
(`apps/api/src/core/driver.ts`): `list`, `start`, `stop`, `restart`, `pull`,
`remove`, `create`, `applyConfig`, `host`. Реализаций две:

| Драйвер | Когда | Что делает |
|---|---|---|
| `MockDriver` | `DOCK_DRIVER=mock` | Выдуманный хост в памяти: сервисы из прототипа, задержки операций, фоновый шум в журнал. Докер не нужен вовсе. |
| `DockerodeDriver` | `DOCK_DRIVER=docker` | Настоящий демон через `/var/run/docker.sock`: инспект контейнеров, статистика, поток логов, pull с прогрессом, создание и пересоздание контейнеров, генерация `compose.yml`. |

Панель разницы не видит: она всегда ходит по реальному HTTP и вебсокету.
Переключение режима — одна переменная окружения, а не ветка в коде.

### Своей базы у панели нет

Метаданные, которых нет у докера — описание, поддомен, участие в бэкапе,
внутренний порт — живут метками на самом контейнере (`dock.managed`, `dock.id`,
`dock.domain`, `dock.volume`, `dock.backup`, `dock.autostart`,
`dock.container-port`). Снёс контейнер — снёс и запись; docker остаётся
единственным источником правды. В `data/` ядро держит только то, что к
контейнерам не относится: `dock.yml` с настройками панели, `state.json` с
отметкой последнего бэкапа и сгенерированные `services/<id>/compose.yml`.

Контейнеры, поднятые не через dock, панель тоже показывает (`DOCK_ADOPT_FOREIGN`),
помечая их как неуправляемые.

### Поток данных

```
браузер ──HTTP──▶ /api/*        действия: start, stop, install, config, settings
        ◀──WS──── /api/stream   снимок при подключении, дальше только дельты
```

Один вебсокет отдаёт всё: строки журнала, снимки сервисов, метрики хоста,
прогресс долгих задач, изменения настроек. Пока сокет живой, панель сервер не
опрашивает. Долгие операции (`pull`, `install`, применение конфига) возвращают
`Job` сразу, а прогресс уезжает событиями — HTTP-запрос не висит, пока тянется
образ.

Контракт лежит в `packages/shared`: сервер регистрирует маршруты из `routes`,
клиент из них же строит запросы, типы событий общие. Рассинхронизироваться
нечему.

### Дизайн-система

`_ds/shff-design-system-…/` — дизайн-система как её отдаёт сборщик DS: токены,
`css/`, `base/`, скомпилированный `_ds_bundle.js`. Она не правится.
`packages/ui` — те же компоненты, перенесённые в TSX один-в-один по разметке и
именам классов; стили импортируются из `_ds`. Обновить дизайн-систему — значит
заменить папку в `_ds/` и поправить путь в `apps/web/vite.config.ts`.

Тема `dock` (циан) задана на `<html data-theme="dock">`, скан-линии
переключаются через `data-crt` из настроек панели.

## Переменные окружения

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `PORT` | `7788` | Порт панели |
| `DOCK_DRIVER` | `mock` | `mock` или `docker` |
| `DOCK_DATA_DIR` | `./data` | `dock.yml`, отметки бэкапов, compose-файлы |
| `DOCK_DOCKER_SOCKET` | `/var/run/docker.sock` | Сокет демона |
| `DOCK_HOST_VOLUME_ROOT` | `/srv` | Корень томов: поле «том» (`dock/gitea`) считается от него |
| `DOCK_HOST_ROOT` | `/` | С какой точки монтирования считается место на диске |
| `DOCK_NETWORK` | `dock` | Сеть для контейнеров, поднятых панелью |
| `DOCK_ADOPT_FOREIGN` | `true` | Показывать чужие контейнеры |
| `DOCK_POLL_INTERVAL` | `4000` | Период пересчёта метрик, мс |
| `DOCK_WEB_DIST` | `apps/web/dist` | Каталог сборки панели |

## Команды

```bash
npm run dev          # ядро и панель параллельно
npm run build        # shared → web → api
npm run typecheck    # все воркспейсы
npm start            # собранное ядро, оно же раздаёт панель
```

## Известные ограничения

- Шрифты подтягиваются с Google Fonts — так их подключает дизайн-система. Для
  честно офлайнового билда положить `.woff2` рядом и переписать
  `_ds/…/tokens/fonts.css` на локальные `@font-face`.
- Экран настроек пишет `dock.yml`, но пока не применяет его к хосту: прокси,
  TLS, cron бэкапов и двухфакторный вход — это конфигурация для соседних
  сервисов, а не для самой панели.
- Кнопка «запустить бэкап сейчас» фиксирует запуск и отметку времени; сам restic
  живёт в своём контейнере.
- Аутентификации у панели нет — она рассчитана на loopback за reverse proxy.
